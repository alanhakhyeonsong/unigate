# 학습 문서 작성

이 프로젝트는 **학습이 1차 목적**이다. 동작하는 코드가 아니라 **왜 그런지 이해한 상태**가 산출물이다.
학습 문서는 커밋 대상 자산이며 (`docs/learning/`), 사용자가 **범위와 주제를 직접 지정해** 요청한다.

## 적용 시점

사용자가 주제를 지정해 요청할 때. 또는 아래 상황에서 **작성을 제안**한다 (임의로 쓰지 않는다).

- `CLAUDE.md` §1.1 의 "처음 접하는 기술"을 실제로 처음 사용한 시점
- 예상과 다르게 동작해 원인을 파악한 시점 — **디버깅 기록이 가장 가치 있다**
- 대안 중 하나를 고른 시점 (선택 기준이 남아야 한다)

---

## 규칙 1: 위치와 이름

```
docs/learning/NN-kebab-case-주제.md
```

`NN` 은 **작성 순서**(= 학습 순서)다. 기존 번호를 재정렬하지 않는다.
다음 번호는 디렉토리의 최대 번호 + 1 로 정한다.

## 규칙 2: 역할 분담 (가장 중요)

> **정책 변경(2026-07-24):** AI 가 §4·§6 포함 전 구간을 직접 작성한다. 사용자는 **모든 Phase
> 작업이 끝난 뒤 한 번에** 검토한다. 상세는 `CLAUDE.md` §2.5.

| 섹션 | 작성자 | 이유 |
|---|---|---|
| 1. 왜 필요했나 | AI | 맥락은 대화에 있다 |
| 2. 익숙한 방식과의 대조 | AI | Servlet/JPA 대응물과 짝지어 설명 |
| 3. 동작 원리 | AI | |
| **4. 직접 확인한 것** | **AI (실측만)** | **실제 실행한 명령·실제 출력만. 추측 금지(환각 방지선)** |
| 5. 함정 / 실패 모드 | AI | |
| **6. 남은 의문** | **AI** | 검증 중 실제로 드러난 미해결 질문 |

**§4 의 불변 규칙:** 반드시 **직접 실행한 명령과 실제 출력**으로만 채운다. 실행하지 않았으면 쓰지
않는다. 비밀번호·토큰·세션 쿠키 원문은 마스킹한다(`CLAUDE.md` §8).

## 규칙 3: 설명 방식

`CLAUDE.md` §1.2 를 따른다. 새 개념은 코드보다 먼저 이 3가지를 쓴다.

1. **대조** — 익숙한 Servlet/JPA/블로킹 방식이면 어떻게 썼을지, 여기선 왜 안 되는지
2. **실패 모드** — 잘못 쓰면 어떤 증상으로 터지는지. 이 스택은 **컴파일 에러가 아니라 부하 시** 터진다
3. **판단 기준** — 선택지가 여럿이면 언제 무엇을 고르는지

모르는 것은 모른다고 하고 공식 문서를 확인한다. **근거 없는 단정을 하지 않는다.**

## 규칙 4: 실제 코드·커밋과 연결

문서 상단에 이 학습이 나온 지점을 남긴다. 맥락 없는 개념 정리는 나중에 안 읽힌다.

```markdown
> 관련: Phase N · 커밋 `abc1234` · 코드 `gateway/src/.../Foo.kt`
```

## 규칙 5: 인덱스 갱신 (누락 금지)

문서를 추가하면 `docs/learning/README.md` 를 갱신한다. **인덱스에 없는 문서는 없는 것과 같다.**

1. "작성된 문서" 표에 한 줄 추가 — 상태는 `학습중` 으로 시작
2. "학습 예정 주제" 목록에 해당 항목이 있으면 체크 표시

상태: `학습중` → `이해함` → (필요 시) `재방문 필요`. **상태 변경은 사용자가 판단한다.**

## 규칙 6: Mermaid

전역 지침의 안전 작성 규칙을 따른다. **모든 노드 라벨을 `["..."]` 로 감싼다.**
`()`, `/`, `:` 등이 포함되면 따옴표 없이는 파싱 에러가 난다.
